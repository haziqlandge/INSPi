## Rulings
- No git commits are made unless the user asks (harness rule overrides the executing-plans skill's per-task commits).
- SQLite via Node's built-in `node:sqlite` instead of better-sqlite3 + Drizzle — no native dependency to compile on Windows; FTS5 verified available. Cost if wrong: swap the one store module.
- Search uses SQL LIKE over name/category/note/tags instead of an FTS5 index — a personal library is small. Cost if wrong: add the FTS table later.
- Multi-frame observations are merged deterministically in code, not by a second AI call — three observations do not fit Groq's free 8K tokens/min. Cost if wrong: less nuanced reconciliation between frames.
- Every provider runs the same two passes (observe, then translate); "single-shot" from the plan is dropped. Large-budget providers just take all frames in one observe call with the full rubric. Cost if wrong: one extra call on generous providers.

## Web prompts become inspiration, parts run in parallel (2026-10-01)
Decided with the user after two outside write-ups (clone vs inspiration): web prompts are **for inspiration only**, and Groq's cap is worked around by **running an analysis's parts on two keys at once**. Combining several references into one design was left for later.
- **web/2 spec.** The blueprint (every section, verbatim copy, exact asset offsets) is gone from new analyses. In its place `patterns`: the page's grammar, its components as reusable blocks (structure, style, importance), the signature `motif` with how to build it and how to `transform` it for another product, and the copy's `voice` (never its words). The observe pass also lists the source's `identity` (logos, names, copy, distinctive illustrations); it never reaches the spec except as a line in `avoid` that always rules those out by name. The translate pass now writes `keep`, `adapt` ("pattern → how to adapt") and a `priority` for each dimension; each finding also gets `basis`: "inferred" for interaction, motion and responsive cues and anything under 0.5 confidence, "observed" otherwise. "Copy prompt" asks for an original site in this language, never the reference's logo, name, copy or illustrations. Older web/1 entries keep their blueprint and old instruction; retry them for a web/2 version.
- Ruling: `basis` is set in code from the dimension and its confidence, not asked of the model — it costs no tokens and cannot drift. Cost if wrong: a finding seen clearly at 0.45 confidence reads as inferred.
- **Parallel parts.** With a second key (`GROQ_API_KEY_FALLBACK`), the patterns and design calls, or the slices when Groq's output cap applies, go out on both keys at once, one request per key at a time; a learned output cap applies to every key. A capped web analysis is now 3 slices (patterns, meta and 10 dimensions, 16 dimensions) instead of 4, with no dependency between them. If one part fails, the others stop before sending anything more. Found and fixed on the way: frames per call was sized by the smallest part's needs instead of the largest.
- Checked live on `test-images/web-linear.png` (`npm run analyze`, not saved to the library): web/2 in 113 s, 5 calls, 13.4K tokens. Components (navigation, hero, product screenshot), the floating-panel motif with a transform for another product, keep/adapt lists, and an avoid line naming the Linear logo, name and UI strings. Groq did not enforce its 1000-a-minute output cap on this run.
- On 1 Oct `GROQ_API_KEY_FALLBACK` was still the same key as `GROQ_API_KEY`, so the parallel path could not help; by 4 Oct the values differ, but nobody has checked that they are separate accounts.

## Subject modes, palette copy, tracker and cost mods (2026-10-04)
- **Why a robot.** Image analysis transfers the style and drops the subject on purpose ("with a subject of your own"), so "Rising Sun Minimal" (a white sports car before a red sun) came back as a robot. Reference tools split this the same way: Midjourney has style reference, omni reference and image prompts; Leonardo has style, content and character references. So Visualize now asks what to do with the subject.
- **Subject modes** (`SubjectChoice` in `lib/copy/compose.ts`): *Recreate it* puts the subject first ("Subject: …") and keeps `subject` in the JSON; *My subject* draws the person's subject and drops the reference's; *Model's choice* is the old prompt and still what Copy prompt gives. Image specs now carry `subject` (the observation's gist). Older entries get one on demand: `POST /api/entries/[id]/subject`, one vision call with the provider in use (logged as a Reading call), saved on the version. The dialog remembers the mode and the reference switch in localStorage (`inspi:visualize-subject`).
- **Showing the model the picture.** Pollinations' `POST /v1/images/edits` takes the prompt plus `image: [{ image_url }]`, a data URI accepted. Free models that take one: GPT Image 2, 1.5 and 1 Mini, MAI Image 2.6 and 2.6 Flash, FLUX.1 Kontext Pro, FLUX.2 Klein (and the community Klein). The entry's first picture goes as a JPEG of at most 1024 px. Only offered when the chosen model takes an image; never through the keyless route.
- **Palette copy.** A click anywhere on a colour copies its hex: the circles on the entry page (the "Palette" label opens the sheet), the sheet's swatches (with a small "Copied" flash; the lock keeps its own job) and the measured bar.
- **Segmented pills** only slide when the choice changes (`layoutDependency`), not when content above moves the control.
- **progress-tracker 0.3.0** (`~/claude-mods/progress-tracker`): both bars are always 300 px wide (36 columns in a terminal), a segment per task (plan) or step (task), each ending in a checkpoint. The open step fills gradually from the work seen on it (tool calls weighted: edits 3, shell 2, others 1; `0.9 × (1 − e^(−w/24))`, never full until ticked). A fill that grows animates; a step landing pops its checkpoint; a task finishing bursts and shimmers with a toast; the plan finishing turns gold. The plan file is checked every 2.5 s and after every tool call, so ticks made by any tool show during a reply. Animations are CSS inside the SVG images (they run in image mode), drawn only while due.
- **cost-ticker 0.4.0**: the engine's cost is per process, so reopening Claude showed $0.00 for the session. Each session now keeps a ledger in the mod's store (`s:<session>`: carried, last, token totals); a lower process cost than last seen means a restart, and what it had reached is carried. Sessions older than the ledger start from their month records.
- **Renders stuck blurred.** DevelopReveal's wash (sepia + blur) was stopped with anime.js `cancel()`, which freezes a value where it stands, so anything that interrupted it (a hidden tab pausing frames, a remount, the effect re-running) left the print blurred. It also forgot a cached image: the load landed before the mount effect reset `loaded`. Now the state is keyed by `src` (plus a `complete` check), it is done when both the wash and the dissolve finish (or after 2.6 s, or at once in a hidden tab), the inline filter is always cleared, and cleanup uses `revert()`.

- **Changes on a new entry.** The New entry window takes a short note of changes from the reference (400 characters). It rides on the job (`jobs.params.changes`), reaches only the translate pass (the observations stay true to the image), is kept on the spec as `changes`, carries over to retries, and every composed prompt states it right after the instruction ("Changes from the reference, which win over anything below: …").
- **Playground subject choice.** "Use an entry's prompt" has the same Recreate it / My subject / Model's choice as the entry's Visualize window (they share the remembered mode), describes an older entry's subject on demand, labels the link ("From X · Recreate it"), and offers "Show the model the original picture" for models that take one.

- **Subject choice per entry.** Image entries are added with a subject choice (default Recreate it), kept on the spec as `subjectMode` / `mySubject` (left out of the JSON a model reads). `composePrompt` defaults to it, so Copy prompt gives the exact or the style-only prompt as chosen; Visualize's window starts from it; retries keep it. The entry page's "Copy prompt gives" switch changes it (`PUT /api/entries/[id]/subject`), describing an older version's subject first when Recreate needs one. Entries added before this keep giving the style-only prompt until switched.
